## Additional traced removals and consolidations

- The map's static `5+5+5` assessment legend was also wrong; it has no consumer beyond presentation and is removed. The assessment screen now counts the actual frozen question kinds, including adapted grammar tasks.
- `challengeScene` in session state was write-only; the DOM scene renderer remains active. `libraryContext`, `stat`, `isDue`, `currentAvailable`, phase renderers and world helpers remain private where needed instead of exposing unused public API entries. The unused `needsOpening` facade never gated a route; the real `placeAccessible` gates are retained and consolidated around the canonical opening (with Day 1 free roam and Day 2’s special route unchanged).
- `contextRomanisation` was already stripped by the builder, making its Library display branch unreachable. The raw pronunciation evidence is retained. Empty lexical `dialect` fields, the never-populated dialect placeholder, unused grammar linkage projection, unused blueprint fields and orphan diagram/path/chip/reset CSS are removed after tracing their producers and readers.
- `SentenceEngine.dialogues` contained one unused local `same` comparison function. Only those two definition lines are removed; no selection, agreement, composition, morphology or dialogue algorithm changes. Before/after compiler payload digests are compared against `688311e`, in addition to the existing exhaustive generation tests.
- `activeUtterance` is deliberately retained despite appearing write-only to a linter: its closure reference holds a Web Speech utterance alive until completion/cancellation. All speech selection, MP3 fallback, delayed voice discovery, request cancellation and native Escape/Library-close handling remain. Library cleanup now centralizes close/focus/audio handling in its actual close event. The lesson Speak button now reads the displayed `activeItem`, rather than the next queue entry after submission.
- Current save validation/reset is retained. Schema 7 stays supported without a migration or forced reset. Choices, disclosure flags and tile permutations are mandatory frozen attempt data; missing fields are rejected and preserved as corrupt, rather than silently regenerated.
- Onboarding selection, reload and explicit reset use the same state-derived pace rendering. First-unstarted-day lookup is shared by the settings UI and planner; existing plans remain frozen. The former `supported(p,data,day)` wrapper only returned all presets and never inspected its first two arguments; it and misleading quota-availability UI are removed. Actual quota shortfalls still come from the planner.

## Intentionally retained behaviour

Grammar catch-up renders each missing workshop through the current day, in day order, before recording those visible rule IDs. Viewing a map or preparing a plan does not unlock grammar. Later or unseen workshops stay locked. Earlier introduced forms remain usable; all sentence generation still requires actual form study and grammar. A truly empty visit shows the rule workshop, attempts productive generation, and records a visit without XP if there is no practice. This keeps opening routes finishable without injecting greetings.

The single curriculum now owns teaching topics, rules, narrative text, lesson participants/teachers and assessment scenes/titles. Runtime lookups reference that data; no authored sentence targets or empty historical course banks are compiled. A pre-cleanup world contract independently checks all fourteen days’ actual people, scenes, story and route gates. All 488 bilingual historical contract records are checked against the unchanged attestation archives as evidence, never teaching content.

## Remaining technical debt

- The lesson and assessment tile renderers still share DOM elements but have deliberately different interaction rules (assessment dud tiles, removable placed words and locked snapshots). They are retained as separate consumers of the shared `QuestionEngine`; unifying their rendering deserves a separate behavioural change.
- Storage writes still catch persistence failures without a dedicated user-facing error state. That existing failure-handling policy is outside this cleanup; valid saves, explicit corrupt/unsupported rejection and deterministic resume are tested.
- Linguistic and pronunciation review remains provisional. No spelling, inflection, translation, verification status or recording is certified by this cleanup. Chromium viewport tests do not replace physical iPhone/Windows audio checks.
